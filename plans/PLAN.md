> 本文件是项目规划的**唯一事实来源**之一（与各 `phase-NN-*.md` 并列）。
> 任何范围、顺序、目标的调整，必须先改本文件。

---

## 一、项目目标

为多份分散在不同共享目录中的 Excel 工作簿提供「签出 → 本地编辑 → 提交」的并发协作能力，替代当前"一人打开、其他人只读等待"的工作方式。配置可登记多份工作簿；每次会话只选择并操作其中一份。

| 项 | 内容 |
|---|---|
| 交付物 | 一个 `.xlam` 加载项，3 个 Ribbon 按钮 |
| 目标用户 | 5 人左右的项目组 |
| 运行环境 | Excel 16.0 x64，Windows，Samba 共享（UNC 访问） |
| 目标文件 | 4 类 `mddt_*` 工作簿，分布在不同 UNC 文件夹；已测样本基线约 11 MB、65 张 sheet，其它目标的规模与结构逐类验收 |

**不可妥协的约束**（详见 `AGENTS.md` §1）：
每份工作簿保持单一共享主文件、纯 VBA、无 M365、本地副本在 `%LOCALAPPDATA%`、配置只存 UNC、不在共享上建临时文件、只用 `Save()`；一次会话只操作一份工作簿。

---

## 二、总体架构

```
┌─ MdlUI ────────── Ribbon 回调、选择窗体、冲突窗体
│
├─ MdlSession ───── 会话状态机
│                   Idle → TargetSelected → CheckingOut → CheckedOut
│                   CheckedOut → Committing ↔ ConflictReview → Committing → Idle
│                   取消裁决或提交失败 → CheckedOut；放弃 → Aborting → Idle
│
├─ MdlExcel ─────── 唯一接触 Excel 对象模型的模块
├─ MdlLock ──────── 列锁：MkDir 互斥 + owner.txt + 心跳 + fencing
├─ MdlMerge ─────── 三方合并（纯数组）
├─ MdlDiff ──────── 逐格比较（纯数组）
├─ MdlSchema ────── 表头解析、AMG/product 列识别、锚点列
│
└─ MdlInfra / MdlStorage ── 日志、错误、路径、工作区、原子改名
```

**依赖方向**：只能自上而下。`MdlMerge` / `MdlDiff` 必须能在**没有 Excel** 的环境下测试。

## 三、用户操作、系统响应与代码职责

本节定义用户可见的端到端行为，以及各 VBA 模块在流程中的职责。这里说明“做什么、整体怎么协作”；具体过程签名、数据结构、算法步骤、错误处理细节和逐项测试放在对应 Phase 计划中。

**使用前提**：加载项已启用，工作簿清单位于 `%LOCALAPPDATA%\MDDTLock\config.ini`。没有配置管理窗体，用户手动维护本机配置文件：首次使用时在文件资源管理器地址栏输入 `%LOCALAPPDATA%\MDDTLock`，若目录不存在则创建；用纯文本编辑器创建或编辑 `config.ini`，每份工作簿占一条 `WorkbookPath=`，只填写 `\\server\share\...` 形式的 UNC 路径。保存后下次点击 “Start Editing” 生效。增加工作簿时增加一行，移除时删除对应行；至少保留一条有效路径且不得重复。映射盘符（如 `X:\...`）拒绝配置。一次会话只选择其中一份工作簿。

配置版本 2 使用 `Version=2` 和重复的 `WorkbookPath=<UNC path>` 行；版本 1 的单条 `MainFilePath=` 保持读取兼容。示例：

```ini
Version=2
WorkbookPath=\\server\share\team-a\mddt_alpha.xlsx
WorkbookPath=\\server\share\team-b\mddt_beta.xlsx
```

缺少配置时界面说明准确位置与创建方式；清单中的路径只在用户选择该工作簿时访问。若文件不存在、共享不可达或无权限，不自动创建或删除路径，显示可判定的具体原因，用户可改配置或选择清单中的其他文件。

| 阶段 | 用户操作与界面反馈 | 后端 VBA 行为与代码职责 | 结果与失败行为 |
|---|---|---|---|
| 启动与配置 | 打开 Excel 并使用加载项；用户首次使用或修改工作簿清单时，手动维护本机配置文件 | 点击“Start Editing”时，`MdlInfra` 读取并校验配置；`MdlSession` 保持 `Idle`，`MdlUI` 根据会话状态启用或禁用按钮 | 配置缺失、格式错误或没有有效条目时提示配置文件位置和修复方式，不开始签出。Excel 启动时不保证已检查配置 |
| 选择工作簿并开始编辑 | 点击“Start Editing”，先从配置清单选择一份工作簿，再选择其 sheet 和要维护的 AMG 列并确认 | `MdlSession` 将所选 UNC 路径固定为本次会话路径；`MdlExcel` 只打开该文件；`MdlSchema` 识别 AMG/product 列、锚点和列名指纹；`MdlLock` 按所选文件、sheet 和 AMG 列获取锁；`MdlStorage` 将该文件复制到 `%LOCALAPPDATA%`；`MdlExcel` 建立 Base 快照 | 配置/文件校验、文件打开或锁获取失败时整组签出失败；明确的文件不存在、权限拒绝、网络不可达分别提示；只读打开提示无法取得写入访问及可能原因；失败不留下活动会话或锁，不自动创建、替换或修复共享文件 |
| 本地编辑 | 在已打开的本地副本中修改声明 AMG 单元格的值、字体（包括一段文字单独着色/加粗）或填充，并按需保存 | 编辑期间不访问共享文件、不挂单元格变更事件；`MdlExcel` 在提交时从当前工作簿内存读取值、逐字符字体 runs 和单元格填充；`MdlDiff` 将 Local 与 Base 按声明范围比较 | 只支持改单元格值和已纳入的字体/填充属性；增删行列和排序不属于本工具范围。未声明的列不会写回；本地编辑不依赖网络可用性 |
| 提交与合并 | 点击“提交”；若有冲突，按文字/字体或填充组件逐项查看 Base、Local、Remote 并选择保留本地或远端组件 | `MdlSession` 使用会话固定的单一 UNC 路径校验锁；`MdlExcel` 读取 Remote 值和格式；`MdlMerge` 按 Base / Local / Remote 分别合并 `TextFont` 与 `Fill`；冲突由 `MdlUI` 按组件裁决；全部裁决后只写回声明列的值和格式并调用 `Save()` | 取消裁决不写共享文件并保留会话；文件缺失、共享不可达、访问受限或 Excel 以只读方式打开时，提交失败且保留本地改动，提示已识别的原因 |
| 提交成功 | 查看成功结果，结束本次编辑 | `MdlExcel` 关闭共享工作簿；`MdlSession` 清理会话并让 `MdlLock` 释放列锁；`MdlStorage` 按本地工作区生命周期规则清理本地副本和 Base | 本次会话结束并回到 `Idle`；继续编辑需重新签出，以取得新的 Base 和锁 |
| 放弃 | 点击“放弃”并确认丢弃本次编辑 | `MdlSession` 进入 `Aborting`；`MdlExcel` 关闭本地副本且不提交；`MdlStorage` 清理本地工作区；`MdlLock` 释放本次列锁 | 回到 `Idle`。清理或释放失败时报告未完成项，避免静默遗留 |

**并发边界**：不同 AMG 列可以在不同会话中并行编辑；同一 sheet + AMG 列只能由一个有效会话持有。提交始终基于最新 Remote 做三方合并，只写回本会话声明的列。共享工作簿的打开、写入和保存协调细节在 Phase 5–7 计划中明确。

**列识别规则**：表头以 `AMG` 开头（大小写不敏感）即为可编辑 AMG 列；非空且不以 `AMG` 开头的表头视为 product 列。行锚点只使用 A–E 范围内识别出的 product 列，并按列序组成锚点；E 列之后的 product 列不参与行锚定。A–E 内没有可用 product 锚点时拒绝签出；最多可有 5 个锚点列。锚点唯一性仍是业务前置条件，不检测。

**同步属性范围**：只比较和同步本次声明 AMG 单元格中的值、直接字体格式和直接填充。字体格式支持整格及 `Characters` 字符段级格式，包含颜色、粗体等直接 Font 属性；填充为单元格级直接 Interior 属性。字体/填充均以规范化纯数据快照参与 Diff/Merge，只有 `MdlExcel` 读写 Excel 对象。

| 属性类别 | 参与比较与同步 | 范围说明 |
|---|---|---|
| 单元格值 | 是 | 仅字符串和空白哨兵；字符串精确比较，公式与其它值类型拒绝 |
| 直接字体 | 是 | 整格及字符段级；同步 Name、Size、Bold、Italic、Underline、Strikethrough、Superscript、Subscript、OutlineFont、Shadow、ColorIndex、Color、ThemeColor、TintAndShade；字符段按原字符串位置保存 |
| 直接填充 | 是 | 单元格级；同步 Pattern、ColorIndex、Color、ThemeColor、TintAndShade、PatternColorIndex、PatternColor、PatternThemeColor、PatternTintAndShade |
| 边框 | 否 | 不检测、不合并、不写回 |
| 对齐与显示 | 否 | 水平/垂直对齐、换行、缩进、文字方向等均不参与 |
| 数字格式 | 否 | `NumberFormat` 不参与；当前可编辑值为字符串 |
| 条件格式及其它规则 | 否 | 条件格式规则不复制；仅处理直接格式，不把屏幕最终显示效果当作单元格直接格式 |
| 命名单元格样式/工作簿主题定义 | 否 | 不复制样式或主题定义；单元格/字符的 Font 与 Interior 属性状态按本表参与 |
| 单元格行为/元数据 | 否 | 数据验证、保护状态、批注/备注、超链接等不参与 |

属性范围严格限于声明 AMG 列和第 2 行至快照末行；未声明列、product 锚点、表头及其它区域的属性不参与 Diff/Merge，也不得写回。
样式或主题对象本身不作为全局对象同步；若应用单元格样式后声明单元格的 Font/Interior 属性状态发生变化，只按这些单元格属性值参与比较和写回，不保留命名样式引用。

格式快照使用版本化、长度前缀编码的纯字符串协议，供 `MdlInfra`、`MdlDiff`、`MdlMerge` 脱离 Excel 比较和合并。`TextFont` 保存值类型标记、原字符串及按相邻字体属性压缩的 `[起始字符, 长度, 字体签名]` runs；空白或零长度字符串保存单元格级字体签名。`Fill` 保存上述固定顺序的属性字段。规范化记录必须可完整解析且与值矩阵中的字符串一致，否则失败关闭。Excel 返回非主题色 `ThemeColor=0` 时规范化为“不适用”，同时忽略对应 TintAndShade；`xlPatternSolid` / `xlPatternNone` 下图案色字段规范化为“不适用”，避免比较 Excel 对不可见字段的自动重写。其它无法稳定读取或写回的字段不降级为无差异。

**冲突粒度决策**：以单元格的 `TextFont`（字符串值 + 完整逐字符直接字体映射）和 `Fill`（整格直接填充）作为两个独立合并组件。三方合并分别判定两个组件：一方改字体、另一方改填充可以自动组合；双方把同一组件改成不同结果时生成该组件冲突。选择整段字体映射作为整体，是因为字符插入/删除会改变位置，逐字符拼接可能把格式套到错误文字；它也减少比较/裁决项数量。代价是双方改了同一格不同字符的字体也会产生一个 `TextFont` 冲突。填充独立处理以避免与字体修改产生无关冲突。

**冲突界面边界**：不提供全量差异预览；仅对三方合并判定为冲突的组件显示 sheet/行/列、组件名及 Base / Local / Remote 数据，并让用户在 Local 与 Remote 中选择。文字/字体预览必须保留字符格式信息；填充预览必须能区分各方直接填充。所有组件选择完成前不进入共享文件写回阶段。

**异常退出**：列锁通过心跳、过期判定和 fencing 阻止失效会话继续提交；本地残留副本的恢复或清理规则由 Phase 7 计划明确。

## 七、测试策略

| 层级 | 范围 | 是否依赖 Excel 工作簿/对象模型 |
|---|---|---|
| 单元测试 | MdlMerge、MdlDiff、MdlSchema 的解析逻辑、MdlInfra 的路径与值/字体/填充规范化数据比较 | 不需要；仅传内存数据 |
| 组件测试 | MdlStorage、MdlLock（用本地临时目录模拟共享） | 不需要；仅用本机文件系统 |
| 集成测试 | MdlExcel、MdlSession | 需要真实 Excel 工作簿/对象模型 |
| 端到端 | 完整签出/提交流程、多人并发 | 需要真实共享环境与客户端 |

当前 VBA runner 会启动受控的隐藏 Excel 进程作为 VBA 执行宿主；“不依赖 Excel”指被测纯逻辑/组件不读取工作簿或 Excel 对象模型，不代表当前有独立于 Excel 的 VBA 运行时。

**强制**：Phase 2/3/4 的产出必须能仅用内存数据测试，且算法不依赖 Excel 工作簿/对象模型。Phase 4 单元测试覆盖无冲突组件合并、冲突识别、逐项选择 Local 或 Remote 后的结果。做不到说明分层失败。
冲突窗体的组件选择、取消裁决后共享文件未被写入，以及签出/提交/放弃的会话行为放在需要 Excel 的集成测试中。

## 八、贯穿全程的工程约束

来自 `prepare/` 的实测结论，任何 Phase 都必须遵守（详见 `AGENTS.md` §4.5）：

- 禁用 `Range.Find`、禁用 `UsedRange` 求边界
- 循环内 `Dim` 不重复初始化 —— 累加量必须显式重置
- 非连续区域禁止 `Union` 读写
- `Application` 事件处理器双保险：`On Error` + `mInCommit` 门闸
- 不用 `wb.Saved` 判断"用户改过"
- 恢复逻辑一律放 `Cleanup:` 标签 + `On Error Resume Next`

## 九、已知的产品级取舍

这些是**明确接受**的不完美，不要试图用技术手段弥补：

| 取舍 | 原因 |
|---|---|
| 不做提交前备份 | 实测 Excel 用 rename 保存，中断不损坏原文件 |
| 不支持增删行列、排序 | 结构变更由工作组离线处理；当前只允许声明 AMG 单元格改值和直接字体/填充 |
| 只同步声明列的值、直接字体和直接填充 | 仅将有意编辑且已确认的属性纳入 Diff/Merge；边框、对齐、数字格式、条件规则及其它单元格行为明确排除 |
| 冲突组件粒度为 `TextFont` 与 `Fill` | 字符串和逐字符字体映射绑定，避免文字位置变化导致不稳定的逐字符拼接；填充独立以减少无关冲突 |
| product 列识别 | 非 AMG 表头列视为 product；仅 A–E 内的 product 列按顺序组成行锚点，最多 5 列 | 对齐已确认的业务语义与锚点位置约定 |
| 可编辑 AMG 列的数据类型 | 仅允许字符串值，不含公式；非字符串值阻止签出或提交 | 避免类型强制转换和公式被值写回覆盖 |
| 多列签出锁冲突 | 任一目标锁失败则整组取消并释放本次已取得的锁，不跳过占用列 | 避免用户误以为部分目标已签出 |
| 锚点唯一性不做检测 | 业务语义保证 |
| SAS 读到旧内容不报错 | 与现状一致，不构成回归 |
| 崩溃后的 `.tmp` 残留只做 24h 清理 | 不影响正确性，不值得复杂机制 |
| 不做全量差异预览 | 只显示必须由用户裁决的冲突单元格，避免增加非必要的预览界面 |
| 多工作簿清单由用户手工维护，且只接受 UNC | 复用本机 `%LOCALAPPDATA%\MDDTLock\config.ini`；版本 2 以重复 `WorkbookPath=` 登记路径，并保留版本 1 单路径读取兼容；不增加 Ribbon 配置入口。路径必须使用 UNC，以避免客户端映射盘符不同造成锁标识不一致；示例和维护步骤见本节及 README |
| 文件打开错误按证据分类 | 预检能确认的文件/目录不存在、访问拒绝、网络不可达和路径为文件夹时分别提示；Excel 返回只读状态时提示无法取得写入访问及可能原因，不断言一定是他人加锁。当前不单独识别 sharing violation |
