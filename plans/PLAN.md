## 一、项目目标

为一份**单一共享 Excel 文件**提供「签出 → 本地编辑 → 提交」的并发协作能力，替代当前"一人打开、其他人只读等待"的工作方式。

| 项 | 内容 |
|---|---|
| 交付物 | 一个 `.xlam` 加载项，3 个 Ribbon 按钮 |
| 目标用户 | 5 人左右的项目组 |
| 运行环境 | Excel 16.0 x64，Windows，Samba 共享（UNC 访问） |
| 目标文件 | 约 11 MB、65 张 sheet、4 类 `mddt_*` 文件 |

**不可妥协的约束**（详见 `AGENTS.md` §1）：
单一文件、纯 VBA、无 M365、本地副本在 `%LOCALAPPDATA%`、配置只存 UNC、不在共享上建临时文件、只用 `Save()`。

---

## 二、总体架构

```
┌─ MdlUI ────────── Ribbon 回调、选择窗体、冲突窗体
│
├─ MdlSession ───── 会话状态机
│                   Idle → TargetSelected → CheckingOut → CheckedOut
│                   CheckedOut → Committing ↔ ConflictReview → Committing → Idle
│                   取消裁决或提交失败 → CheckedOut；放弃 → Aborting → Idle
│
├─ MdlExcel ─────── 唯一接触 Excel 对象模型的模块
├─ MdlLock ──────── 列锁：MkDir 互斥 + owner.txt + 心跳 + fencing
├─ MdlMerge ─────── 三方合并（纯数组）
├─ MdlDiff ──────── 逐格比较（纯数组）
├─ MdlSchema ────── 表头解析、AMG/product 列识别、锚点列
│
└─ MdlInfra / MdlStorage ── 日志、错误、路径、工作区、原子改名
```

**依赖方向**：只能自上而下。`MdlMerge` / `MdlDiff` 必须能在**没有 Excel** 的环境下测试。

## 三、用户操作、系统响应与代码职责

本节定义用户可见的端到端行为，以及各 VBA 模块在流程中的职责。这里说明“做什么、整体怎么协作”；具体过程签名、数据结构、算法步骤、错误处理细节和逐项测试放在对应 Phase 计划中。

**使用前提**：加载项已启用，用户配置中已有可访问的 UNC 主文件路径。加载项只接受 UNC 配置，不依赖映射盘符。

| 阶段 | 用户操作与界面反馈 | 后端 VBA 行为与代码职责 | 结果与失败行为 |
|---|---|---|---|
| 启动 | 打开 Excel 并使用加载项 | `MdlInfra` 读取配置并检查主文件路径；`MdlSession` 保持 `Idle`，`MdlUI` 根据会话状态启用或禁用操作按钮 | 配置缺失或路径不可用时给出明确提示，不开始签出 |
| 开始编辑（签出） | 点击“开始编辑”，选择一个或多个 sheet 及各自要维护的 AMG 列，然后确认 | `MdlSchema` 识别可编辑 AMG 列、product 锚点列和列名指纹；`MdlSession` 校验目标并切换状态；`MdlLock` 获取每个 sheet + AMG 列的锁并在编辑期间续约；`MdlStorage` 将共享文件复制到 `%LOCALAPPDATA%`；`MdlExcel` 打开本地副本并读取选中范围，建立 Base 快照 | 成功后用户只编辑本地副本。当前按整组选中范围处理：任一目标校验或锁获取失败时，本次签出整体失败，释放本次已取得的锁并说明原因；不留下活动会话。是否支持跳过不可用目标，留待 Phase 5/7 计划确认 |
| 本地编辑 | 在已打开的本地副本中修改值并按需保存 | 编辑期间不访问共享文件、不挂单元格变更事件；`MdlExcel` 在提交时从当前工作簿内存读取值，`MdlDiff` 将 Local 与 Base 按声明范围逐格比较 | 只支持修改值；增删行列和排序不属于本工具范围。未声明的列不会写回；本地编辑不依赖网络可用性 |
| 提交与合并 | 点击“提交”；若有冲突，逐格查看 Base、Local、Remote 并选择保留本地值或远端值 | `MdlSession` 校验会话和锁仍有效；`MdlExcel` 读取共享文件当前 Remote；`MdlMerge` 按 Base / Local / Remote 逐格合并，单侧修改自动保留，双方改成不同值的单元格交由 `MdlUI` 逐格裁决；全部冲突完成裁决后，`MdlExcel` 只把合并结果写入声明的 AMG 列，校验结果并调用 `Save()` | 用户取消冲突裁决时不写共享文件，保留本地副本、会话和列锁供稍后继续；提交前校验失败或共享文件无法安全打开时不保存共享文件，保留本地改动并提示原因；保存失败也保留本地改动并报告结果 |
| 提交成功 | 查看成功结果，结束本次编辑 | `MdlExcel` 关闭共享工作簿；`MdlSession` 清理会话并让 `MdlLock` 释放列锁；`MdlStorage` 按本地工作区生命周期规则清理本地副本和 Base | 本次会话结束并回到 `Idle`；继续编辑需重新签出，以取得新的 Base 和锁 |
| 放弃 | 点击“放弃”并确认丢弃本次编辑 | `MdlSession` 进入 `Aborting`；`MdlExcel` 关闭本地副本且不提交；`MdlStorage` 清理本地工作区；`MdlLock` 释放本次列锁 | 回到 `Idle`。清理或释放失败时报告未完成项，避免静默遗留 |

**并发边界**：不同 AMG 列可以在不同会话中并行编辑；同一 sheet + AMG 列只能由一个有效会话持有。提交始终基于最新 Remote 做三方合并，只写回本会话声明的列。共享工作簿的打开、写入和保存协调细节在 Phase 5–7 计划中明确。

**冲突界面边界**：不提供全量差异预览；仅对三方合并判定为冲突的单元格逐格显示位置及 Base / Local / Remote 值，并让用户在 Local 与 Remote 中选择。所有选择完成前不进入共享文件写回阶段。

**异常退出**：列锁通过心跳、过期判定和 fencing 阻止失效会话继续提交；本地残留副本的恢复或清理规则由 Phase 7 计划明确。

原则：**先做能脱离 Excel 验证的纯逻辑，再做需要 Excel 的，最后做集成**。
每个 Phase 结束时必须是可独立验证的状态。

| Phase | 名称 | 产物 | 依赖 | 状态 |
|---|---|---|---|---|
| **0** | 项目初始化 | 目录骨架、`AGENTS.md`、`PLAN.md`、`.gitignore`、git 仓库 | — | ✅ 已完成 |
| **1** | 基础设施 | `MdlInfra`：日志、错误包装、路径/UNC 解析、延迟探测 | Phase 0 | ⬜ 待开始 |
| **2** | 表结构解析 | `MdlSchema`：表头解析、AMG/product 列、锚点列、列名指纹 | Phase 1 | ⬜ 待开始 |
| **3** | 差异检测 | `MdlDiff`：声明列内逐单元格值比较、变更集合 | Phase 1 | ⬜ 待开始 |
| **4** | 三方合并 | `MdlMerge`：Base/Local/Remote 合并、冲突判定与逐格选择结果应用 | Phase 3 | ⬜ 待开始 |
| **5** | 列锁 | `MdlLock` + `MdlStorage`：MkDir 锁、owner.txt、心跳、fencing、过期回收 | Phase 2 | ⬜ 待开始 |

| **7** | 会话状态机 | `MdlSession`：签出/提交/冲突裁决/放弃编排、本地工作区生命周期 | Phase 4, 5, 6 | ⬜ 待开始 |

## 五、各 Phase 的一句话目标

| Phase | 完成后能得到什么 |

| 1 | 任何模块都能记日志、包装错误、把 `X:` 解析成 UNC、测出当前延迟 |

## 八、贯穿全程的工程约束

来自 `prepare/` 的实测结论，任何 Phase 都必须遵守（详见 `AGENTS.md` §4.5）：

- 禁用 `Range.Find`、禁用 `UsedRange` 求边界
- 循环内 `Dim` 不重复初始化 —— 累加量必须显式重置
- 非连续区域禁止 `Union` 读写
- `Application` 事件处理器双保险：`On Error` + `mInCommit` 门闸
- 不用 `wb.Saved` 判断"用户改过"
- 恢复逻辑一律放 `Cleanup:` 标签 + `On Error Resume Next`

## 九、已知的产品级取舍

这些是**明确接受**的不完美，不要试图用技术手段弥补：

| 取舍 | 原因 |
|---|---|
| 不做提交前备份 | 实测 Excel 用 rename 保存，中断不损坏原文件 |
| 不支持增删行列、排序 | 结构变更由工作组离线处理，工具只做改值 |
| 只比较声明列的单元格值 | 当前仅支持值修改；格式属性不参与 diff、merge 或写回，避免引入未确认的冲突和写回范围 |
| 锚点唯一性不做检测 | 业务语义保证 |
| SAS 读到旧内容不报错 | 与现状一致，不构成回归 |
| 崩溃后的 `.tmp` 残留只做 24h 清理 | 不影响正确性，不值得复杂机制 |
| 不做全量差异预览 | 只显示必须由用户裁决的冲突单元格，避免增加非必要的预览界面 |
